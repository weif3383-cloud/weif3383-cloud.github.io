今天是學資安的第一天，先把基礎觀念、網路和密碼學的入門整理起來。

## 資安核心觀念

**CIA 三要素**：所有資安問題都能歸到這三類。

- **機密性（C）**：只有該看的人看得到，例如密碼外洩
- **完整性（I）**：資料沒被偷偷竄改，例如成績被改
- **可用性（A）**：需要時用得到，例如網站被打掛、檔案被勒索加密

真實事件常常是複合的，像勒索軟體的「雙重勒索」就是先偷資料（C）再加密（A）。

- **漏洞**是系統的弱點，**威脅**是可能利用弱點的人或事，**風險**是發生的可能性 × 損失。資安的目標不是絕對安全，而是把風險降到可以接受。
- **攻擊面**是所有可能被攻擊的入口總和（開著的 Port、輸入框、USB 孔、客服人員……）。攻擊者找最弱的入口，防守者關掉不必要的入口。

## 身分與權限

- **驗證（AuthN）**：你是誰？**授權（AuthZ）**：你能做什麼？順序永遠是先驗證、再授權。
- **IDOR**：有驗證、漏了授權。例如把網址 `/order?id=1001` 改成 `1002` 就看到別人的訂單，因為系統只確認你有登入，沒檢查那筆資料是不是你的。
- **最小權限**：只給剛好夠用的權限，帳號被盜時損害有限。
- **縱深防禦**：不要只靠一道牆，要一層一層防。
- **MFA** 要結合兩種「不同類型」的因素（你知道的／你擁有的／你本身的）。密碼加安全提問都是「你知道的」，不算真正的 MFA。

## 網路基礎

- **IP** 決定送到哪一台電腦；**Port** 是一個號碼，電腦收到網路資料後，看 Port 決定要交給哪個正在聽這個號碼的程式（例如網頁伺服器聽 443）。
- **TCP** 像掛號信，可靠但稍慢，用在登入、傳檔、網頁；**UDP** 像發傳單，快但可能掉，用在視訊、遊戲、DNS。
- **DNS** 是網路電話簿，把網址翻成 IP。**DNS 欺騙**會把你導到假網站，網址列卻看起來正常。
- **NAT** 會順便擋掉從外面主動連進來的連線，但它**不是防火牆**，設了 Port 轉發就等於開門。

| Port | 服務 | 用途 |
|---|---|---|
| 22 | SSH | 遠端登入 Linux |
| 53 | DNS | 網址查 IP |
| 80 | HTTP | 網頁（未加密） |
| 443 | HTTPS | 網頁（加密） |
| 3389 | RDP | Windows 遠端桌面 |

每個對外開著的 Port 都是攻擊面。22 和 3389 能直接控制整台機器，不該直接對網路開放。

### 輸入網址按 Enter 後發生什麼事

```
DNS 查 IP → TCP 三次握手 → TLS 握手（憑證 + 加密）→ HTTP 請求 → HTTP 回應 → 畫面
```

- **TCP 三次握手**是 SYN → SYN-ACK → ACK。**SYN Flood** 就是只送第一句不回，讓伺服器一直傻等，破壞可用性。
- **HTTPS = HTTP + TLS + TCP**：TLS 負責加密和驗證對方身分，TCP 負責可靠送達，兩者是上下疊的關係。
- 沒有 TLS 的 HTTP 會用明文傳密碼，同一個 Wi-Fi 的人都可能看到，這就是**中間人攻擊**。

**鎖頭 🔒 只保證**傳輸途中有加密、連到的是這個網域本人。它**不保證**網站是好人（釣魚網站也能有鎖頭）、資料到伺服器後是安全的，也不保證你的電腦沒中毒。所以看到鎖頭之外，也要確認網址有沒有拼對。

## 密碼該怎麼存

- **不要自己發明加密演算法**，安全靠的是被全世界公開檢驗也打不破，不是靠沒人知道怎麼運作。
- **加密**可逆，有鑰匙就能還原；**雜湊**不可逆，故意設計成解不回來。密碼要用**雜湊**存，登入時把輸入的密碼再雜湊一次來比對。所以正派網站忘記密碼只能重設，不能把原密碼寄給你。
- **碰撞**：不同輸入得到同一個雜湊值。能被故意製造碰撞的演算法（MD5、SHA-1）已經被淘汰。
- **加鹽**：雜湊前給每個密碼摻一段獨一無二的隨機字串，相同密碼也會得到不同結果，讓彩虹表失效。鹽不是秘密，可以跟雜湊值存在一起。
- **慢雜湊**（bcrypt、Argon2）故意算得很慢，讓暴力猜測不划算。

> 結論：用 bcrypt 或 Argon2 這類慢速雜湊，每個密碼都加鹽。
